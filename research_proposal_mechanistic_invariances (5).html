We cannot evaluate an RL agent's reasoning — only its actions. This research changes that: a three-layer system that extracts causal circuits from a trained policy, monitors them at deployment to produce behavioral correction before failure occurs, and repairs circuit drift durably — catching goal misgeneralization, reward hacking, and world model exploitation without retraining.

Core Claim: Multiple RL failure modes — goal misgeneralization, reward hacking, specification gaming, world model exploitation — share a common mechanistic root: the agent's internal reasoning becomes causally miscalibrated. We propose a three-layer system that (1) extracts causal circuit invariances offline via SAE and activation patching, (2) monitors them at deployment using EAP and emits R_reason to produce behavioral correction before failure occurs, and (3) uses violation records to guide targeted fine-tuning or activation steering for durable repair. Violations fire before behavioral degradation appears. Behavioral correction prevents failure without retraining. The full pipeline does not exist in any prior work.

§ 01

The Problem

Model-Based Reinforcement Learning agents are evaluated entirely on what they do — actions taken, rewards received. No mechanism exists to evaluate how they think — the internal reasoning process that produced those actions.

An agent can learn to produce correct actions during training via spurious internal reasoning — routing through proxy features that co-occurred with reward rather than features that causally determine it. On the training distribution this is invisible. At deployment, when the environment shifts, the spurious reasoning collapses.

This single structural failure — causally miscalibrated reasoning — manifests as multiple distinct failure modes depending on how the spurious routing plays out. All of them are currently undetectable until after behavioral failure occurs.

The Silent Failure Chain — Shared Root
① Agent trains on world model — actions look correct on training distribution
② Internally routes through causally invalid pathways — spurious features, shortcuts, proxy correlations
③ Environment shifts at deployment — spurious reasoning collapses
④ Silent failure — no process-level signal fired before the cliff
The Core Gap
No existing method detects causal reasoning failure before it manifests behaviorally. There is no process-level signal — only outcome-level observation, too late to act on.
The Four Failure Modes — One Mechanistic Root
Failure Mode A
Goal Misgeneralization
Capability generalizes, goal does not. Agent pursues proxy goal at deployment because it over-weighted proxy features during training. Caught by I3 + I4
Failure Mode B
Reward Hacking
Agent finds a shortcut path through the world model that bypasses genuine causal reasoning — satisfying the reward signal via an invalid internal route. Caught by I1 + I2
Failure Mode C
World Model Exploitation
Policy routes through hallucinated world model dynamics — features that activate in model rollouts but are causally invalid in the real environment. Caught by I2 + I5
Failure Mode D
Specification Gaming
Agent satisfies the literal reward signal via a causally wrong reasoning chain — correct output, wrong process, guaranteed to fail under any non-trivial distribution shift. Caught by I1 + I2 + I5
All four share the same structural root — causally miscalibrated internal reasoning. Our method detects the root, not the symptoms. Goal misgeneralization is the primary empirical testbed because it is the cleanest controlled setting — not the only failure mode we address.
§ 02

The Model We Apply This To

Primary Setting
PPO / SAC policy trained directly on observations — procedurally generated environments (Procgen, MiniGrid/BabyAI)
Why SAE Works Here
A single deep policy network — IMPALA CNN or small transformer — processes raw pixels through multiple intermediate layers. Rich enough computation for SAE to extract meaningful monosemantic features and build a causal graph with genuine depth.
Why Procgen / MiniGrid
Procedurally generated — you control exactly which visual features co-occur with reward during training and which break at test time. Goal misgeneralization is already demonstrated here (Langosco et al. ICML 2022). Distribution shift is inducible at a known step.
No Ambiguity
One network to analyze. No world model / actor separation. The policy receives observations and outputs actions — the full causal reasoning chain is in a single inspectable forward pass. SAE, circuit analysis, and causal graph construction are applied to this one network.
Secondary Setting — Generality Demonstration
Actor-critic agent within MBRL — DreamerV3 on DMControl continuous control
The actor network inside DreamerV3 receives the world model's latent state and outputs actions — this is the decision-making network we apply SAE and circuit analysis to. The world model introduces a second layer of spurious learning: the actor can route through world model hallucinations in addition to environment-level spurious correlations, making reasoning miscalibration more acute and the failure modes more compounded than in the primary setting.
SAE Target
Actor network forward pass — from latent world model state through actor layers to action output. Separate analysis on RSSM for world model exploitation detection (I2 + I5).
What It Demonstrates
Method generalises to MBRL — a structurally different RL paradigm with a latent-space actor. Supports the general causal reasoning integrity verifier claim beyond single-network policies.

§ 04

What Solving This Enables

The Reframe
Prior safety methods ask: "did the agent do something bad?" — outcome-level, after the fact. This method asks: "is the agent currently reasoning in a way that will produce bad behavior?" — process-level, before the fact. That shift is the contribution. And because violations fire k steps before behavioral failure, there is a window to act on that signal — to correct behavior before it degrades.
01 · Early Warning
Before behavioral failure — across all four failure modes
Goal misgeneralization, reward hacking, world model exploitation, specification gaming — all produce causally miscalibrated reasoning before they produce wrong actions. A process-level signal detects the miscalibration, not the symptom.
02 · Mechanistic Diagnosis
Which failure mode, why, and where
I1 firing alone → shortcut bypass (reward hacking / specification gaming). I3+I4 firing → goal drift (misgeneralization). I2+I5 firing → invalid world model route. The invariance pattern identifies the failure mode, not just its existence.
03 · Behavioral Correction
Prevents failure without retraining
R_reason fires k steps early and feeds back as a dense per-step signal. PPO updates the action distribution away from violation-triggering states — behaviorally correcting the agent before failure manifests. Not circuit repair: the agent averts failure by changing what it does, not by fixing its internal representations. That is enough, and it is currently unsolvable without our method.
04 · Durable Repair
Circuit-level fix between episodes
Violation records — which features drifted, how far, in which direction — guide targeted fine-tuning or activation steering between deployment episodes. The agent is repaired at the representation level so it no longer needs the behavioral safety net. Layer 2 is the bandage. Layer 3 is the cure.

§ 07

The Core Idea — A Three-Layer Safety System

Core Insight
Goal misgeneralization, reward hacking, specification gaming, and world model exploitation all produce the same internal signature: causally miscalibrated reasoning. We detect the signature before behavioral failure, correct the agent's behaviour in real time, and repair the underlying circuit drift durably.

When an RL agent makes a decision, its internal forward pass traces a reasoning path — from input features through intermediate representations to the action output. That path has structure. It can be extracted, analyzed, and verified.

Certain causal properties of that reasoning path should remain invariant under distribution shift — not because we freeze the specific path, but because those properties reflect the causal structure of the MDP itself rather than surface correlations in training data.

This is not a goal misgeneralization detector. It is a causal reasoning integrity verifier. Goal misgeneralization is one failure mode that produces a reasoning integrity violation. Reward hacking, specification gaming, and world model exploitation are three others — all caught by the same five invariances, each with a distinct violation signature.

What We Penalize vs. Allow
✓ Agent adapts its reasoning path — new features become relevant
✓ Valid training-time edges lose weight as environment changes
✗ Known-spurious edges gain weight (reward hacking / spec gaming)
✗ True goal features drop out of chain entirely (misgeneralization)
✗ Reasoning becomes shallow — input→action direct (shortcut)
✗ Graph is self-inconsistent — claimed cause does not drive action (world model exploitation)
§ 08

Methodology

Full Pipeline — Training to Deployment
Phase 1 — Extract Causal Circuits During Training
1
Train PPO/SAC policy on Procgen or MiniGrid until convergence. Freeze all weights. Train Top-K SAEs on the frozen policy's activations across all layers using a large offline rollout corpus — extracting interpretable, monosemantic features at each layer.
2
Apply full activation patching offline. For each feature pair (i, j) across layers, run counterfactual forward passes: zero out feature i, measure change in feature j. Edges surviving intervention are causally valid. Edges that fail are flagged spurious — stored in the spurious edge set S.
3
Build G_t per decision. Nodes = active features per layer. Directed edges = causally validated influences. Weights = causal strength. Aggregate across training into reference statistics per cluster of state types.
4
Extract the five causal invariant profiles from G* — causal depth baseline (I1), spurious edge set S (I2), goal feature set F_goal (I3), proxy feature weight ceilings (I4), and self-consistency baseline (I5). Freeze these as the reference. Validate EAP correlation against patching on a held-out rollout set (target r > 0.9) before deployment.
Causal Circuit — What G_t Looks Like Inside The Agent
SAE extracts features at each layer. Circuit analysis builds directed causal edges between them. Edge weight encodes causal strength validated by do-calculus intervention.
The Five Causal Invariances — click to expand
Each invariance is independently motivated by causal theory, independently testable, and independently robust to distribution shift.
I1
Invariance 1
Causal Depth
Reasoning chain must have sufficient intermediate steps between input features and action. A shallow input→action direct connection is a shortcut in any environment — it means the agent is pattern-matching, not reasoning.
Bidirectional check
I2
Invariance 2
Spurious Edge Absence
Edges that failed intervention testing during training — known-invalid pathways — must not gain weight at deployment. Valid edges losing weight is allowed. Only the re-entry of pre-identified bad pathways is penalized.
One-directional — blocks bad entry only
I3
Invariance 3
Goal Feature Dependence
Features causally linked to the true reward signal must remain somewhere in the reasoning chain. If the agent stops routing through true goal features entirely, it has undergone goal misgeneralization — regardless of what new path it found.
Presence check — path may change
I4
Invariance 4
Proxy Feature Independence
Features that correlated with reward during training but failed causal validation must not become dominant drivers at deployment. Their causal weight must stay below training-time baselines.
Weight ceiling check
I5
Invariance 5
Causal Self-Consistency
The feature the agent's graph identifies as the dominant cause must actually drive the action under intervention. If zeroing that feature does not change the action, the graph is self-inconsistent. Requires no reference to training — distribution-shift robust by construction.
Live intervention — no training baseline needed
Spotting Violations At Deployment — G_live vs G*
After distribution shift, the agent's live circuit diverges from the frozen reference. Each failure mode produces a distinct structural signature mapped to a specific invariance violation.
The Complete System
Three layers working together: extract offline, monitor live, repair durably
Layer 1 · Offline
Circuit Extraction
Build G* once, offline, using full activation patching. High fidelity, no time pressure. Freeze as the reference invariant profile.
Layer 2 · Real-Time
Monitor + Behavioral Correction
EAP at every step. Compare G_live against G*. Emit R_reason. PPO updates action distribution away from violation-triggering states. The safety net — prevents failure without fixing the circuit.
Layer 3 · Between Episodes
Targeted Repair
Violation records from deployment guide a targeted fine-tuning objective or activation steering vector. Addresses the specific feature drift directly. The cure, not just the bandage.
Layer 2 — Real-Time Monitor + Behavioral Correction
A
Standard forward pass through frozen policy + frozen Top-K SAEs. Every decision produces the live feature activation vector.
B
Single backward pass over K active features computes the K×K Jacobian. EAP edge weights wliveij = |fi · ∂fj/∂fi| built in microseconds.
C
I1–I4 check G_live against frozen G* profiles — fast matrix comparison. I5 runs one counterfactual forward pass only when I1–I4 flag a violation.
D
R_reason emitted. PPO update makes violation-triggering actions less probable. Agent behaviorally corrects — avoids states and actions that produce miscalibrated circuits.
What Behavioral Correction Actually Does

R_reason does not directly fix the causal circuit. It makes the agent less likely to take the actions that led to circuit miscalibration. This is the safety net — the agent averts the failure by changing its behavior, not by repairing its representations. That is enough to prevent the failure from occurring. The circuit repair happens in Layer 3.

The Reward Objective
Rtotal = Renv + λ(t) · Rreason
where
Rreason = −(α · Vdrop + β · Vgain + γ · 𝟙[I5])
Vdrop catches goal feature collapse (I3+I4). Vgain catches spurious edge re-entry (I2). I5 fires on self-inconsistency. λ(t) decays as agent proves stability.
What Violation Records Accumulate
→ Which invariances fired at which steps
→ Which features drifted and in which direction
→ How far each edge weight moved from G*
→ The full causal diagnosis — passed to Layer 3
Layer 3 — Targeted Repair (Between Episodes)
Option A — Targeted Fine-Tuning
Between-episode weight repair
Violation records identify exactly which features drifted and which edges changed. Construct a fine-tuning loss that directly penalizes the observed drift. Run a small number of gradient steps. Redeploy with repaired weights.
Durable repair · weight-level fix · no inference cost
Option B — Activation Steering
Mid-episode representation repair
When I5 fires and the circuit identifies that avoid_signal weight collapsed, directly inject a steering vector at the relevant layer to boost that feature's activation. Correction happens at the source — the feature weight — bypassing the gradient path entirely.
Mid-episode · activation-level · no fine-tuning needed
Why Behavioral Correction + Targeted Repair Together

Layer 2 is the traction control — it prevents the wheels from spinning on the ice without fixing the ice. Layer 3 is the repair — it fixes the underlying condition so the agent no longer needs the safety net. Together they form the first complete deployment-time safety system for MBRL agents: detect early, correct behaviorally, repair durably. No prior work offers all three layers.

§ 10

Feasibility Study — Building The Causal Graph At Deployment

The frozen trained model is straightforward — you build G* offline using full activation patching, with unlimited compute and no time pressure. The hard question is what happens when the model is live, inferencing at real-time, and you need a causal graph every single step.

The Core Tension
Building a true causal graph requires counterfactual interventions — running multiple forward passes per step. That destroys your frame rate. So what do you do instead?

Full activation patching at K=32 features across L layers means hundreds of forward passes per decision step. At 60fps that is thousands of forward passes per second. Completely infeasible. The question is which approximation is principled enough to be defensible and fast enough to be real.

The Three Approaches — In Order Of Causal Validity
Approach 1
Full Activation Patching
Deployment infeasible
Gold standard

Zero out feature i, measure change in feature j. Repeat for every pair. True do-calculus — actual causal intervention, not an approximation. This is what gives you ground truth and is what you use to build G* at training time.

Use for: Building G* offline. Every patching experiment you need, no time constraint, full causal validity.
Why not at deployment: K×L forward passes per step. At 60fps this is thousands of forward passes per second. Completely infeasible.
Approach 2
Edge Attribution Patching (EAP)
Recommended
Deployment feasible

First-order Taylor approximation of the patching result. One backward pass. The edge weight approximates what full patching would give you without running a single extra forward pass.

The EAP Edge Weight Formula
wijlive = | fi(L1) · ∂fj(L2) / ∂fi(L1) |
The instantaneous Jacobian multiplied by the feature activation. Computes how much feature i at layer L1 causally drives feature j at layer L2 at this exact forward pass.
The Key Insight — Top-K Sparsity Makes This Blazingly Fast
In a standard network, computing gradients between all neurons is an O(N²) problem. But Top-K SAEs force 99.9% of features to hard zero. Only K features are active per layer. You only need gradients across a K×K submatrix of active elements — for K=32 that is 1,024 elements versus potentially millions. One backward pass. Fractions of a millisecond.
Theoretical grounding: EAP validated against activation patching in transformer circuits literature — Marks et al. 2023. Citable. Reviewers will recognise it.
Known weakness: First-order approximation diverges from true patching when the network is strongly nonlinear. Requires offline validation that EAP correlates with patching on your specific architecture (r > 0.9 target).
Approach 3
SCM Proxy Distillation
Future work
Fastest possible

Train a small auxiliary network at training time to predict causal edge weights directly from the SAE feature activation vector. At deployment: one tiny forward pass through the proxy, no backward pass at all. No gradients, no Jacobians.

Why interesting: Faster than EAP. If the mapping from active features to edge weights is learnable, you can distill the entire causal graph into a single forward pass through a tiny network.
Why not yet: Unvalidated anywhere. The proxy may not generalize to unseen deployment states — exactly when you need it most. Worth a sentence in future work, not a core claim.
The Violation Score — Comparing G_live Against G*
Weight Collapse — I3 + I4 Detection
Vdrop = Σ(i,j) ∈ G* max(0, w*ij − wliveij)
Fires when training-time causal edges lose weight. Catches goal feature dropout (I3) and spurious proxy dominance (I4).
Edge Re-Entry — I2 Detection
Vgain = Σ(i,j) ∈ spurious max(0, wliveij − w*ij)
Fires when flagged-spurious edges gain weight at deployment. Catches reward hacking and shortcut bypass (I2). A term the original formulation was missing.
Combined Violation Score
Vtotal = α · Vdrop + β · Vgain + γ · 𝟙[I5 fires]
Rreason = − Vtotal · λ(t)
What The Paper Must Claim — Training vs Deployment Split
Training Time — Offline, Expensive, High-Fidelity
→ Train policy to convergence, freeze weights
→ Train Top-K SAEs on frozen activations across all layers
→ Build G* using full activation patching across rollout corpus
→ Flag spurious edges, identify goal features, compute proxy ceilings
→ Validate EAP correlation with patching on held-out rollouts
→ Freeze G* as the invariant reference profile
Deployment Time — Online, Fast, EAP-Based
→ Standard forward pass through frozen policy + frozen Top-K SAEs
→ Single backward pass over K active features → K×K Jacobian
→ Compute wliveij = |fi · ∂fj/∂fi| for all active pairs
→ Check I1–I4 via matrix comparison against frozen G* — microseconds
→ If flagged: run I5 — one counterfactual forward pass, check action
→ Emit Rreason as dense per-step reward signal
The Claim That Reviewers Will Respect

G* is constructed offline using full activation patching — true causal intervention, computationally expensive, done once. G_live is constructed at deployment using EAP — a first-order approximation validated offline to correlate with patching at r > 0.9, requiring one backward pass over K active features per step. Top-K SAE sparsity reduces this to a K×K computation, making it feasible in real time. The expensive causal analysis done once at training time is sufficient to define cheap runtime checks that catch failures early.

Does R_reason Actually Correct The Agent?
The Honest Answer
R_reason does not fix the causal circuit. It prevents the failure from occurring by changing the agent's behavior. That is enough — and it is the right goal.

You do not care whether the internal circuit is beautiful. You care whether the agent stops failing. Goal misgeneralization means wrong actions at deployment. If R_reason prevents those wrong actions — the failure is averted. The circuit being miscalibrated is the diagnostic signal, not the failure criterion.

The Gradient Path — What R_reason Actually Updates
R_reason fires
→
PPO loss updates
→
policy weights Δθ
→
different actions
→
different observations
→
different circuit

The circuit is at the end of a long indirect chain. PPO updates the action distribution — it makes violation-triggering actions less probable. The agent avoids the states and actions that produce miscalibrated circuits. This is behavioral correction, not representation repair. Both are valuable. They are not the same thing.

Why Behavioral Correction Is The Right Goal
Goal misgeneralization is currently considered nearly impossible to correct at deployment without retraining. The standard view: if an agent has goal-misgeneralized, you must retrain it with more diverse data. You cannot fix it in deployment.
If behavioral correction via R_reason prevents goal misgeneralization from manifesting as actual wrong actions — without retraining, without environment reset — that solves a problem that currently has no solution.
Process reward models (OpenAI PRMs) give per-step reward based on reasoning quality. R_reason is structurally identical — a mechanistically-grounded PRM derived from internal circuit analysis rather than external evaluation.
RL reshapes circuits — recent work shows online RL post-training increases activation intensity and diversity. The gradient path from R_reason to circuit structure exists and has empirical precedent.
The Complete Contribution — Detection + Correction + Repair
Causal reasoning invariance violations fire k steps before behavioral failure (Layer 2 detection). The resulting reward signal produces behavioral correction that prevents failure from occurring (Layer 2 correction). Violation records guide targeted repair that fixes the underlying circuit drift (Layer 3). Together: the first complete deployment-time safety system for MBRL agents.

No prior work offers all three. The detection result alone is publishable. Detection plus behavioral correction is a strong Accept. Detection plus behavioral correction plus durable repair is the paper you are trying to write.

§ 11

Possible Ways To Take This Research To The Next Level

A method paper gets accepted. A discovery paper gets a Strong Accept. The difference is not effort or completeness — it is whether your experiments reveal something the community did not know was true about RL agents. Below are the specific pivots that could take this from a solid contribution to an unforgettable one.

The Reframe That Changes Everything
Method Paper — Accept
"Our method detects reasoning failures before behavioral ones. Here is the engineering pipeline."
Reviewer response: Interesting engineering pipeline. What does it discover about RL agents?
Discovery Paper — Strong Accept
"Successful RL policies possess stable causal reasoning invariants — and violating those invariants is a necessary precursor to goal misgeneralization."
Reviewer response: We found a previously unknown mechanistic precursor to RL failure.
The Three Questions That Determine Whether You Have A Discovery
Q1
Do causal reasoning invariants actually stabilize during training?
Measure I1–I5 across the full training curve. Do they converge and stabilize as the agent learns a good policy? If yes — causal reasoning invariants are not something you impose on the agent, they are something the agent develops. That is a scientific finding about RL agents independent of any safety application. It changes how people think about what learning produces.
Q2
Is the violation gap k large enough to matter?
k = 5 steps is a marginal engineering result. k = 50+ steps is a phenomenon. k = 100+ steps means you have detected goal misgeneralization before any behavioral signal could possibly catch it — before the agent has even encountered a meaningful number of shifted states. Design the experiment to measure k precisely. The size of k is the empirical heart of the paper.
Q3
Does the phenomenon generalize — across environments and architectures?
Same invariance stabilization in Procgen, MiniGrid, and DreamerV3 actor-critic. Same k-step gap across goal misgeneralization, reward hacking, and world model exploitation. Same signature across CNN and transformer policies. If yes — you have discovered a general property of trained RL agents, not an artifact of one environment or architecture.
